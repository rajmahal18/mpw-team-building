# Updated Ten-Phase Roadmap

## Phase 1 — Research & Product Constitution

**Status: COMPLETE**

Research, product mantra, no-hardcoding doctrine, activity/configuration universe, government/privacy/safety baseline, PWA/QR direction.

## Phase 2 — Domain Model & Configuration Schemas

**Status: COMPLETE**

Completed contracts:

- domain model and ERD;
- hybrid relational + typed JSON persistence strategy;
- Prisma proposal;
- activity/question/config contracts;
- block/plugin registries;
- declarative rule engine;
- raw metric/scoring/result model;
- lifecycle state machines;
- immutable versions/snapshots/randomization;
- optional-account identity model;
- capability-based RBAC;
- audit/domain-event taxonomy;
- validation/preflight invariants;
- 16 materially different example configurations;
- architecture proof matrix;
- Phase 3 repository contract.

**Exit test passed conceptually:** Amazing Race checkpoint, arbitrary quiz, physical timed game, quantity challenge, judged performance, free-roam scavenger hunt, tournament activity, bonus activity, reflection, and unknown future physical game all fit without title-based logic or dedicated named-game tables.

## Phase 3 — Repository Foundation & Multi-Event Core

**Status: COMPLETE**

Create the actual Next.js/TypeScript/Prisma repository and implement the minimum generic vertical slice. Frontend visual polish remains intentionally deferred.

## Phase 4 — Organizer Event Builder & Activity Library

**Status: COMPLETE**

Reusable event configuration, arbitrary teams/roster, organization-level versioned activity library, template materialization, and organizer workspace implemented. Final visual polish remains deferred.

## Phase 5 — Activity + Question/Content Builder

**Status: COMPLETE**

Visual block authoring, arbitrary question structures, question banks/random draw, hints/attempts/timer contracts, participant-safe preview, generic auto-grading, visual scoring expressions, and declarative rule editing implemented.

## Phase 6 — Flow, QR, Stations & Live Operations

**Status: COMPLETE (packaged with Phase 7)**

Stations, routes, signed/rotatable QR credentials, route-aware checkpoint visits, marshal operations, queue/capacity handling, live control, rerouting and announcements implemented.

## Phase 7 — Scoring, Competitions & Leaderboards

**Status: COMPLETE**

Append-only score ledger operations, raw metric/derived score placement conversion, weighted/best-N/drop-lowest event aggregation, tie-break chains, live standings, immutable result revisions, round-robin and single-elimination plugins implemented.

## Phase 8 — Participant PWA, Offline Resilience & Media

**Status: COMPLETE**

Mobile-first participant runtime, optional installable PWA shell, device-local safe offline snapshots, durable IndexedDB submission/media outbox, reconnect sync, media proof/moderation, low-data mode, event gallery, and public/participant/projector leaderboard surfaces implemented.

## Phase 9 — Government Hardening, Reports & Accessibility

**Status: COMPLETE**

Government-oriented security/privacy hardening, report exports, audit viewer, privacy notices, PIA/data-subject-request/incident records, retention controls, backup evidence, security headers, rate limiting, media authorization, accessibility baseline, and operational runbooks implemented. The app remains explicit that agency/DPO approval is required for legal compliance decisions.

## Phase 10 — MPW Production Event & Reusable Library Expansion

**Status: COMPLETE — v1.0 PRODUCTIZATION**

Final visual system, event-aware participant theming, organizer information architecture refinement, projector polish, provider-neutral deployment automation, structured observability hooks, acceptance/release runbooks, and reusable pilot procedures implemented. Real-event execution remains an operational activity rather than hardcoded application behavior.
